# D-0006 — Set It Down's tags follow the classes

**The ask.** The handoff's §4.4 and phase 6: once the shapes settle, give Set It Down size and stacking tags
for the solid items, re-checked against the geometry ("an item that read as flat as a sprite may now be a
chunky 3D object and belong in the other tag").

**Decision.**

- `devtools/art/build.py` writes `data/setitdown/tags/item/size/{small,tiny}.json` and
  `stackable_{pile,cluster}.json` from every item's class: its `size`, and `STACKING` (flat things pile:
  ingots, nuggets, bricks, plates, books, discs, rods, steaks, cookies, loaves, pies, sandwiches; lumpy
  things cluster: ores, lumps, gems, shards, dusts, orbs, fruit, eggs, berries, roots, tubers,
  drumsticks, fish; the rest one to a spot). Every entry is `required: false`, so a mod the pack lacks is
  skipped. Tags are data, so **Heft's jar must be on the server** for them to apply. Its code loads
  nothing client-side there (the gametests prove it).
- **Tags only add.** Set It Down reads long > tool > small > tiny, and pile > cluster. Where its own tags
  already say otherwise, the higher wins. Measured against its explicit entries, 2026-10-26:
  - gems and shards (diamond, emerald, amethyst, lapis, quartz) stay **piles** (Set It Down's), not
    clusters. Left so: the round gem piles well enough;
  - orbs, the cookie and the egg stay **small** (Set It Down's), not tiny;
  - **beef, pork and mutton, raw and cooked, now pile** (Heft's pile outranks Set It Down's cluster): a
    flat steak climbs as a slab where it used to spread. A change to Set It Down's behaviour, flagged to
    Rusty.
- Not tagged: plants and spawn eggs (drawn at runtime, by kind), and the long tail. Set It Down's own
  rules and `c:` tags cover them as before.
